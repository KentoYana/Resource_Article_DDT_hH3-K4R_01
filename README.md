# Resource_Article_DDT_hH3-K4R_01

This repository contains datasets, analysis scripts, and generated output files associated with the following manuscript:

> Yanagisawa K, Tomoda Y, Yoshihara R, Hatakeyama S, and Tanaka S.
> **Histone H3K4 methylation-related chromatin regulation modulates UV-induced mutagenic outcomes and RecQ-associated DNA damage tolerance in *Neurospora crassa***

This repository provides the input data, analysis scripts, and output files needed to inspect and reproduce the analyses reported in the manuscript. The files are organized by analysis.

The resource version associated with the manuscript is
[v1.1.7](https://github.com/KentoYana/Resource_Article_DDT_hH3-K4R_01/releases/tag/v1.1.7).

Version v1.1.7 includes the race-tube workflow in `07_race_tube`, the original
images in `08_source_images`, and the qSpot representative-image and strain-ID
guide. These additions are absent from v1.1.6; the original analysis inputs,
scripts and numerical outputs in the earlier workflows are unchanged.

## Contents

### `01_killing_test`

This directory provides the data and R script for the UV killing-test analysis.

Main files:

- `dataset/killing_data.csv`: raw killing-test data.
- `dataset/strain_list.csv`: strain and genotype annotation table.
- `script_killing_test.R`: R script for data processing, within-biological-replicate normalization, AUC analysis, paired Holm-adjusted comparisons, and figure generation.
- `output/`: processed data, replicate-level AUC values, statistical summaries, comparison results, session information, and TikZ figure output.

In `killing_data.csv`, `Date` identifies the biological replicate. The four biological replicates were initiated independently from the strain stocks. The three rows for each strain and ultraviolet dose within a biological replicate are technical replicates; the script averages them before normalization and AUC calculation.

Run from the repository root:

```sh
Rscript 01_killing_test/script_killing_test.R
```

### `02_reversion_assay`

This directory provides the data and R script for the reversion-frequency analysis.

Main files:

- `dataset/reversion_data.csv`: raw reversion-assay data.
- `dataset/strain_list.csv`: strain annotation table.
- `dataset/genotype_list.csv`: genotype annotation table.
- `script_reversion_frequency_AUC.R`: R script for reversion-frequency calculation, baseline-corrected AUC analysis, Holm-adjusted Welch comparisons, and figure generation.
- `output/`: processed data, AUC data, pairwise comparison results, Welch-test summaries, session information, and TikZ figure output.

In `reversion_data.csv`, `Date` identifies the biological replicate. Technical replicates are averaged within each biological replicate, strain, and ultraviolet dose before the reversion frequency and baseline-corrected AUC are calculated.

Run from the repository root:

```sh
Rscript 02_reversion_assay/script_reversion_frequency_AUC.R
```

### `03_seq_analysis`

This directory provides the data and scripts for sequence-based analysis of `pan-2` revertants.

Main files:

- `dataset/reversion_sequence.csv`: revertant sequence information.
- `dataset/pan-2_genomic.fasta`: reference genomic sequence for `pan-2`.
- `dataset/strain_list.csv`: strain annotation table.
- `run_palindrome_OGW1.zsh`: shell script that runs EMBOSS `palindrome` and extracts inverted-repeat candidates from the first 80 bp of the analyzed sequence.
- `script_rev_seq_analysis.R`: R script for indel extraction, positional summaries, indel-size analysis, negative-binomial GLM analysis, and figure generation.
- `run_clustalo_B36.zsh`: shell script for generating a Clustal-format alignment using Clustal Omega.
- `output/`: generated EMBOSS output, inverted-repeat tables, processed sequence data, indel summaries, statistical results, FASTA files, alignment files, and TikZ figure output.

The inverted-repeat files used by the R analysis are generated by `run_palindrome_OGW1.zsh`, including:

- `output/palindrome.txt`
- `output/ir_candidates.csv`
- `output/ir_pairs.csv`

Run the sequence-analysis workflow from the repository root in the following order:

```sh
zsh 03_seq_analysis/run_palindrome_OGW1.zsh
Rscript 03_seq_analysis/script_rev_seq_analysis.R
zsh 03_seq_analysis/run_clustalo_B36.zsh
```

Run the first step before the R script because `script_rev_seq_analysis.R` reads `output/ir_pairs.csv`.

### `04_quantitative_spot_test`

This directory provides the original plate images, SpotScanner measurements, strain annotations, and R script for quantitative spot-test analysis.

Main files and directories:

- `dataset/exp_list.csv`: experiment list and image-suspension code used to select the source-image series for each analysis.
- `dataset/qSpot-*`: target-specific datasets containing original JPEG plate images, the corresponding SpotScanner result CSV files, and strain annotation tables.
- `script_qSpot_test.R`: R script for importing SpotScanner results, fitting beta-regression response curves, normalizing model predictions to 0 J within each biological replicate, calculating pairwise and interaction AUC contrasts with delta-method uncertainty, testing AUC equivalence, applying BH correction, and generating figures.
- `output/`: processed data, model summaries, standardized response curves with pointwise confidence intervals, target-specific pairwise, interaction, and equivalence AUC results, session information, and TikZ figure output.

The target-specific dataset directories are:

- `qSpot-mei-3`
- `qSpot-mus-11`
- `qSpot-mus-26-polh`
- `qSpot-mus-9`
- `qSpot-recQ`
- `qSpot-uvs-2`

Within each target-specific directory, every `SpotYYMMDD` subdirectory corresponds to one biological replicate and records its plate-imaging date. Cultures for different biological replicates were initiated independently from the corresponding strain stocks. Directories named `results_YYYY-MM-DD_HH-MM-SS` record when SpotScanner analyzed the corresponding images. The imaging and analysis dates can differ; for example, plates imaged on 2023-06-01 were processed on 2024-02-08.

The `exp_ID` field used internally by `script_qSpot_test.R` is the identifier for the biological replicate.

Each archived source image has a corresponding `*_results.csv` file, and each archived result CSV has a corresponding source image. `script_qSpot_test.R` uses these CSV files as its direct quantitative inputs.

Each target-specific `strain_list.csv` records the initial conidial concentration used for every strain. The image-suspension code in an image filename identifies the source-image series and is not assumed to be the actual starting concentration of every strain on that plate. For each strain, the analysis calculates the concentration at dilution column $d$ as `initial_conidia_per_ml / 5^(d - 1)`.

For every biological replicate and ultraviolet dose, the two plates prepared from the same conidial suspension are technical replicates. Their available spot measurements are averaged within genotype and dilution step and rounded to two decimal places. Observations with a corresponding 0 J/m² control mean of zero are excluded before calculation of the spot-coverage ratio. Each target's `output/<target>/excluded_zero_control.csv` lists these observations; a header-only file indicates that none were excluded.

Ratios above one are capped at one. The endpoint adjustment `(x * (n - 1) + 0.5) / n` uses the number of observations retained for that target, as does the transformation of relative conidial input. Four zero-control observations are excluded from the mus-9 set, leaving 380 observations. Each of the other five sets retains 288 observations.

#### SpotScanner image analysis

Plate images were quantified using SpotScanner version 7.0.0. The software is available at <https://github.com/KentoYana/spotscanner>.

Most images were processed in batch mode:

```sh
spotscanner -a pipette -m
```

The `pipette` analysis mode used the default threshold of 7. Batch mode (`-m`) applies the single-image routine invoked by `-s` to each input image.

A small number of images required individual processing with an explicit threshold:

```sh
spotscanner -a pipette -s <image-file> -t <threshold>
```

SpotScanner reports the fraction of each predefined grid-based region of interest covered by the detected spot, calculated from the covered pixels. It records the threshold used for each image in the corresponding output CSV file. The archived CSV files also contain the analysis timestamp, image identifier, row and column coordinates, and measured spot coverage. These records identify any image-specific threshold adjustment.

Run the downstream statistical analysis from the repository root:

```sh
Rscript 04_quantitative_spot_test/script_qSpot_test.R
```

## Notes on TikZ figure files

Some plots are exported as TikZ/PGFPlots `.tex` files using the R package `tikzDevice`.

These files are editable figure sources. Axis labels, legend labels, panel labels, text placement, and other presentation-level details may be adjusted directly in the generated TeX source before inclusion in the manuscript or figure-assembly workflow.

Rerunning an analysis script may overwrite manual TeX-level edits. Keep a separate copy of edited TeX files or reapply the edits after regeneration.

The killing-test script assigns compact-letter groups from Holm-adjusted AUC comparisons, whereas the qSpot script uses BH-adjusted pairwise AUC comparisons. For every qSpot target, the script also calculates the AUC interaction contrast and a two-one-sided equivalence test for the background-mutant versus background-mutant-plus-`hH3-K4R` contrast. Equivalence is defined using an author-selected margin of +/-0.10 on dose-range-standardized AUC, corresponding to 10 percentage points in mean normalized spot coverage. When the background mutant and its hH3-K4R combination share the same AUC-group letter, the qSpot figure displays the equivalence-test p-value; when their letters differ, it displays the pairwise AUC-comparison p-value that determines the letter separation. The formal AUC-interaction analysis remains unchanged and is retained in the output tables. The tracked presentation copies retain the established figure layout.

Some presentation details require manual correction after regeneration. `tikzDevice` emits an oversized outer drawing region, can place endpoint group letters too close together, and does not preserve all gene-name italics. The corrected details include bounding boxes, clip regions, unit typography, overlapping letter coordinates, and gene-name typography.

## Repository hygiene

Files specific to a local operating system or interactive R session are not required for reproducibility and are excluded through `.gitignore`. Examples include:

- `.DS_Store`
- `._*`
- `__MACOSX/`
- `.RData`
- `.Rhistory`
- `.Rproj.user/`
- local cache and environment files

The published repository should remain free of these files.
